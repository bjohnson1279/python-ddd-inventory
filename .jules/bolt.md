## 2024-05-18 - Optimize stock level deduction in OrderRoutingEngine
* **Bottleneck:** The `OrderRoutingEngine` had a bottleneck in its `route_order` and `_get_available_qty` methods where it sequentially searched through the list of `stock_levels` (which could be large) every time it needed to check available quantity or deduct allocated stock for a given location and SKU.
* **Learning:** This inner loop inside the `route_order` method resulted in an O(M*K*N) time complexity where M is order lines, K is locations, and N is stock levels. By initializing an internal dictionary `self.stock_lookup` that maps `(location_id, sku)` to the respective `StockLevel` objects during `__init__`, we can optimize this to O(M*K) since the dictionary provides O(1) lookups. Modifying the `StockLevel` object inside the dictionary directly updates the original instance.
* **Measurement:** A synthetic benchmark testing the routing functionality with a high number of iterations (200 locations, 1000 skus, 100 order lines) yielded an average execution time improvement from ~1.45 seconds to ~0.0011 seconds.
